如今，几乎每个人都知道物联网是什么，或者听说过一些相关信息。
一个非正式的定义可能是"万物互联"。
然而，更精确地说，物联网（IoT）正在扩展传统上为特定设备保留的常规连接，使其几乎可以覆盖我们能想象到的任何类型的设备，从农场和农田中的小型传感器到医院中的生命监护仪。
据估计，到 2020 年，将有 500 亿这样的设备相互连接（[@evans2011cisco](https://www.cisco.com/c/dam/en_us/about/ac79/docs/innov/IoT_IBSG_0411FINAL.pdf)）。
这 500 亿设备共同需要的一件事是通信，这正是中间件在这个庞大技术挑战中发挥重要作用的地方。
中间件负责简化网络部署，使开发者能够专注于应用实现。

本文将介绍两种为物联网设计和开发的标准：MQTT 和 DDS-XRCE。

## MQTT

消息队列遥测传输（MQTT）是物联网解决方案中使用最广泛的协议之一。
它被设计为一种轻量级消息协议，用于 TCP 传输，提供了一个标准且简单的发布/订阅接口来交换数据。

MQTT 的通信机制基于客户端-服务器架构。
这意味着客户端（MQTT 客户端）连接到服务器（MQTT 代理），后者负责使用发布-订阅消息模式协调数据交换。
换句话说，客户端在代理上发布与特定主题相关联的消息，代理将这些消息重定向到订阅该主题的客户端。

因此，在 MQTT 中，我们可以谈到一些关键概念：代理、客户端、主题、消息、发布和订阅。
这些概念各有其角色和含义：

* 代理充当系统的骨干，处理主题消息。
* 客户端是负责从代理发布和接收订阅数据的部分。
* 主题是信息通道。
* 消息是特定主题上的信息片段。
* 发布是将消息发送到代理以供特定主题使用的操作。
* 订阅是表示有兴趣接收特定主题所有消息的操作，由代理处理。

所有这些都是通过 TCP 协议完成的，允许客户端和代理通过广域网和互联网连接。
这种连接是静态建立的，即客户端必须在首次连接之前知道代理的地址。
这些通信可以遵循三种不同的 QoS 来指定交付行为：

| QoS | 保证交付 | 防重复 |
|:-:|:-:|:-:|
| QoS0 | 否 | 否 |
| QoS1 | 是 | 否 |
| QoS2 | 是 | 是 |

如前所述，在这类中间件中有主题的概念。
主题的类型由应用程序设置，以及其名称。
发布使用主题名称和一组用户定义格式的数据完成。
